# Тимчасові директорії на запит + суфікс `_xN` в імені результату

**Дата:** 2026-07-18
**Статус:** затверджено

## Проблема

Зараз сервіс уникає колізій імен, додаючи unix-timestamp як префікс до імені файлу
(`receiveRequest`, handlers.go): `1730000000_model.gcode`. Цей префікс потрапляє в
`Content-Disposition`, тож користувач завантажує файл із незручним технічним ім'ям.

## Рішення

Ізолювати кожен запит у власній тимчасовій директорії, а користувачу повертати файл
з чистим ім'ям і суфіксом `_xN` перед розширенням, де N — кількість ітерацій.

```
files/
└── job-1a2b3c4d/              ← тимчасова директорія запиту (os.MkdirTemp)
    ├── model.gcode            ← вхідний файл, оригінальне очищене ім'я
    └── model_x5.gcode         ← результат; саме це ім'я отримує користувач
```

Після відповіді директорія видаляється одним `os.RemoveAll`.

## Потік обробки (`internal/webserver/handlers.go`)

1. **`receiveRequest`** створює директорію `os.MkdirTemp("files", "job-*")` —
   унікальність гарантує stdlib, timestamp більше не потрібен. Завантажений файл
   зберігається в неї під очищеним оригінальним ім'ям. Сигнатура змінюється:
   повертає `(req, workDir, err)`.
2. **`UploadHandler`** будує ім'я результату: суфікс `_x<Iterations>` вставляється
   перед розширенням (`path.Ext`): `model.gcode` + 5 → `model_x5.gcode`;
   без розширення → `name_x5`. Результат пишеться в ту саму директорію.
   Прибирання: `defer os.RemoveAll(workDir)` (замість двох `os.Remove`).
3. **`sendResponse`** віддає файл результату з заголовком `Content-Disposition`
   від `mime.FormatMediaType`: token-імена без лапок
   (`attachment; filename=model_x5.gcode`), імена з пробілами — в лапках,
   не-ASCII — `attachment; filename*=utf-8''%D0%BC...` (RFC 6266). Клієнт
   (`www/script.js`) розбирає всі три форми, `filename*` має пріоритет.

## Безпека

Оригінальне ім'я тепер використовується напряму, тому:

- **Очищення імені**: беремо базове ім'я — відкидаємо все до останнього `/` або `\`
  (Windows-браузери можуть надсилати повний шлях); результат `..`, `.` або порожній
  рядок → fallback `input.gcode`. Це закриває path traversal, від якого раніше
  випадково захищав timestamp-префікс.
- **`Content-Disposition`** формується через `mime.FormatMediaType` замість сирого
  `fmt.Sprintf` — коректне екранування лапок і не-ASCII імен.

## Зміни в коді

| Місце | Зміна |
|---|---|
| `handlers.go: receiveRequest` | MkdirTemp, очищення імені, повертає workDir |
| `handlers.go: UploadHandler` | шляхи in/out у workDir, ім'я `_xN`, RemoveAll |
| `handlers.go: sendResponse` | приймає шлях до файлу + download-ім'я; FormatMediaType |
| `processor.go: ProcessingRequest.FileName` | зберігає лише очищене оригінальне ім'я (використовується тільки webserver-ом) |
| `main.go` | створює лише `files/`; на старті видаляє залишки `files/job-*` після падінь |
| `handlers_test.go` | оновлення наявних тестів + нові кейси |
| `www/script.js` | розбір `Content-Disposition`: `filename*`, лапки, bare token |

## Обробка помилок

- `MkdirTemp` не вдався → помилка з `receiveRequest`, як усі інші (наразі 400).
- Помилка збереження файлу → директорія видаляється, помилка повертається.
- Помилку `os.RemoveAll` у defer логувати через slog (не ігнорувати мовчки).
- Помилка чистки `files/job-*` на старті — лог-warning, не фатальна.

## Тести

- Оновити: `Content-Disposition` містить `model_x5.gcode` без timestamp;
  тести `receiveRequest` перевіряють файл у workDir.
- Нові кейси: ім'я без розширення; ім'я з `../../`; ім'я з лапками та кирилицею;
  директорія відсутня після завершення запиту (успіх і помилка обробки).

## Поза обсягом

- Формат `filename*` (RFC 5987) понад те, що дає `mime.FormatMediaType`.
- Ліміти на кількість одночасних тимчасових директорій.
